## Описание проекта

TilGuard(Qazaq Loc QA) проверяет локализацию в ARB-файлах и помогает подготовить исправления для проверки человеком. Основные языки проекта — казахский и узбекский. Русский файл используется как источник для сравнения.

Инструмент создаёт JSON с находками и автономный HTML-отчёт. В HTML можно найти нужную строку, посмотреть причину предупреждения, записать решение и скачать его в JSON. Согласованные изменения применяются отдельной командой; сам запуск проверки перевод не меняет.

Версия: **0.1.2**. Для работы нужен **Python 3.10 или новее**. Базовый режим не требует внешних Python-зависимостей. Gemini подключается по желанию.

## Что входит в сдачу

| Файл или папка | Назначение |
|---|---|
| `locqa/`, `tests/`, `examples/`, `scripts/`, `pyproject.toml` | Исходный код, тесты и синтетические примеры (корень репозитория) |
| `report.json` | Основные находки по итоговому переводу |
| `report.html` | Тот же отчёт для просмотра и ручной проверки |
| `report.candidates.json` | Находки с уверенностью ниже рабочего порога |
| `glossary.csv` | Термины на русском, казахском и английском, комментарии, правила сопоставления и колонка `status` (`approved` применяется при проверке, `reference` нет) |
| `intl_kk_fixed.arb` | Исправленный казахский перевод с отметками проверки человеком |
| `METHODOLOGY.md` | Методика, подтверждённые результаты и ограничения |
| `evidence_by_human/` | Решения проверяющих, журнал нормализации и материалы проверки Flutter |

`pyproject.toml`, `glossary.csv` и папка `locqa` находятся в корне репозитория на одном уровне. Глоссарий нужен в том числе для запуска тестов. Окружение `env`, папки `build`, `out`, кеши Python и файлы IDE в репозиторий не входят (см. `.gitignore`).

Файлы с реальными данными (`intl_kk_fixed.arb`, отчёты, `evidence_by_human/`) сданы организаторам в репозитории сдачи по условиям кейса. Репозиторий сдачи должен оставаться закрытым. Для открытой публикации подготовьте отдельную копию без реальных данных и их истории в Git; одного удаления файлов из последнего коммита недостаточно.

## Установка на Windows

Откройте CMD в корне репозитория, в папке с `pyproject.toml`. Выполните:

```cmd
py -m venv env
env\Scripts\activate.bat
python -m pip install .
python -m locqa --version
```

Ожидаемая версия — `0.1.2`. Ниже команды для кода и примеров выполняются из этой же папки с активным окружением.

Если редактируете исходники и хотите запускать их из другой папки, установите пакет в режиме разработки:

```cmd
python -m pip install -e .
```

Узнать, какая копия генератора отчёта используется:

```cmd
python -c "import locqa.report; print(locqa.report.__file__)"
```

## Быстрая проверка на примерах

В `examples` находятся синтетические ARB с заранее подготовленными ошибками. Для проверки ключ Gemini не нужен.

```cmd
python -m locqa check --source examples\intl_ru.arb --target examples\intl_kk.arb --glossary glossary.csv --with-meta --out out\examples_report.json
start "" "out\examples_report.html"
```

Для поставляемых примеров при стандартных настройках ожидаются 90 ключей, 25 основных находок и 3 дополнительных кандидата.

## Проверка своих ARB

Все команды выполняются из корня проекта: папки с `pyproject.toml`, `glossary.csv` и каталогом `locqa`. Предварительно установите инструмент и активируйте окружение по инструкции выше.

### Куда положить данные

Создайте папку:

```cmd
mkdir data
```

Скопируйте в неё `intl_ru.arb` (русский оригинал) и `intl_kk.arb` (казахский перевод). Сопоставление выполняется по ключам сообщений; отсутствующие ключи перевода будут отмечены в отчёте. Глоссарий `glossary.csv` находится в корне проекта. Для своего глоссария используйте колонки `ru`, `kk`, `en`; несколько допустимых переводов в `kk` разделяются символом `|`.

В поставляемом глоссарии статус `approved` включает автоматическую проверку термина, а `reference` оставляет запись справочной. Если колонка `status` отсутствует, записи по умолчанию участвуют в проверке.

### Как запустить проверку

```cmd
python -m locqa check --source data\intl_ru.arb --target data\intl_kk.arb --glossary glossary.csv --out out\report.json
```

Результаты сохраняются в `out`:

| Файл | Содержимое |
|---|---|
| `report.json` | Массив основных находок |
| `report.html` | Интерактивный отчёт для просмотра и ручной проверки |
| `report.candidates.json` | Дополнительные находки с уверенностью ниже 0.5, если они есть |

Исходные ARB при проверке не изменяются. Папка `out` создаётся автоматически.

Чтобы дополнительно сохранить сводку с версией, числом проверенных ключей и распределением предупреждений:

```cmd
python -m locqa check --source data\intl_ru.arb --target data\intl_kk.arb --glossary glossary.csv --with-meta --out out\report_meta.json
```

Без `--with-meta` JSON содержит массив находок, с этим параметром — объект с полями `summary` и `findings`. Сдаваемый корневой `report.json` использует массив по схеме ТЗ.

Основной отчёт по умолчанию содержит находки с `confidence >= 0.5`. Чтобы включить все срабатывания:

```cmd
python -m locqa check --source data\intl_ru.arb --target data\intl_kk.arb --glossary glossary.csv --min-confidence 0 --out out\report_all.json
```

Пути с пробелами заключайте в двойные кавычки. Если локаль нельзя определить по имени файла или полю `@@locale`, добавьте `--locale kk` или `--locale uz`.

### Как открыть результат

```cmd
start "" "out\report.html"
```

Можно также открыть HTML двойным щелчком. Сервер и интернет для просмотра не нужны. Чтобы открыть уже приложенный итоговый отчёт из корня репозитория, выполните `start "" "report.html"`.

## Какие ошибки ищет инструмент

| Тип | Что проверяется |
|---|---|
| `untranslated` | Отсутствующий ключ или пустой перевод |
| `same_as_source` | Совпадение с исходником с исключениями для брендов, чисел и некоторых общих слов |
| `placeholder_mismatch` | Имена плейсхолдеров, скобки и типы простых ICU-аргументов |
| `plural_mismatch` | ICU plural/select, обязательная ветка `other`, явные селекторы и offset |
| `glossary_violation` | Соответствие терминам и допустимым вариантам из глоссария |
| `length_overflow` | Рост длины коротких элементов интерфейса |
| `machine_translation_suspect` | Признаки кальки, русского порядка слов и русской грамматики |
| `inconsistent_term` | Разные переводы одинаковых исходников и терминов |
| `suffix_harmony` | Жёстко заданные окончания после подставляемых значений |
| `orthography` | Опечатки, смешение алфавитов и вероятные подмены казахских букв |
| `wrong_language` | Признаки текста на другом языке |

У каждой находки есть ключ, тип, критичность, оригинал, перевод, объяснение, возможное исправление, уверенность и отметка ручной проверки. Дополнительный `id` помогает сопоставлять решения с конкретными находками.

`severity` определяет приоритет разбора. `confidence` — внутренняя оценка правила, а не измеренная вероятность ошибки. Предупреждение не является готовым языковым заключением. Например, длинная строка может корректно помещаться в интерфейсе, а два разных перевода могут быть допустимы в разных контекстах.

## Как пользоваться HTML-отчётом

### Сводка и диаграммы

Вверху показаны общее количество находок, распределение по критичности и число проверенных находок. Полоска и круговая диаграмма отображают доли High, Medium и Low.

Критичность помогает расставить приоритеты, но не означает, что предупреждение подтверждено человеком. Счётчик «Проверено» относится к решениям в открытом отчёте: ноль в новом HTML не отменяет отметки предыдущей проверки в ARB.

### Поиск и фильтры

Нажмите на тип проблемы, чтобы отфильтровать список. Поиск позволяет найти ключ, текст или объяснение. Выпадающие списки ограничивают результаты по критичности и уверенности. Кнопка «Сбросить фильтры» возвращает полный список.

### Карточка находки

Карточка содержит ключ, тип проблемы, критичность, уверенность, русский оригинал и текущий перевод. Поле «Почему» объясняет срабатывание правила; «Предложение» содержит возможное исправление, если оно есть. Предложение нужно оценить по смыслу и контексту игры.

### Проверка человеком

1. Укажите имя в поле «Проверяющий».
2. Включите «Режим проверки носителем».
3. Прочитайте оригинал, перевод и объяснение.
4. Примите предложение, сохраните свой вариант или отклоните ложное предупреждение.
5. При недостатке контекста отложите решение и добавьте комментарий. Для динамических окончаний можно отметить необходимость обработки в коде.

В исправленном тексте сохраняйте имена плейсхолдеров в фигурных скобках, структуру ICU и необходимые теги. Несохранённый текст в поле редактирования не заменяет сохранённое решение.

### Экспорт и продолжение работы

Нажмите «Скачать decisions.json», чтобы сохранить решения отдельным файлом. Для продолжения используйте «Загрузить решения». Импорт проверяет соответствие находкам и не применяет частично конфликтующий файл.

Решения также хранятся в браузере, но могут исчезнуть после очистки его данных. Сохраняйте JSON отдельно. Скачанный файл решений ещё не является исправленным ARB: для его получения используется команда `apply` из следующего раздела.

## Применение исправлений

Положите скачанный `decisions.json` в корень проекта. Решения должны относиться к той версии строк, по которой сформирован отчёт:

```cmd
python -m locqa apply --source data\intl_ru.arb --target data\intl_kk.arb --decisions decisions.json --out out\intl_kk_fixed.arb
python -m locqa validate out\intl_kk_fixed.arb --template data\intl_ru.arb
```

`apply` проверяет исходные тексты, совместимость плейсхолдеров и ICU, отклоняет устаревшие и конфликтующие решения. Итог сохраняется через временный файл с атомарной заменой после локальной валидации. Входные файлы нельзя использовать как выход.

В метаданных `@ключ` сохраняются `x-reviewed_by_human`, проверяющий, исходный текст и история изменений. В подготовленном итоговом файле дополнительные подтверждения носителем отражены также через `x-reviewed_by_native`. История сохраняет прежние статусы: первоначальная автоматическая правка могла иметь `false`, а её позднее человеческое подтверждение — `true`.

`validate` проверяет локальную структуру ARB, базовые имена ресурсов, метаданные и контракт ICU. Он **не запускает Flutter**. Успешный `validate` не заменяет стандартный `flutter gen-l10n`.

## Как воспроизвести проверку сдаваемого перевода

Сначала установите CLI (раздел «Установка на Windows»). Затем откройте CMD в корне репозитория, где лежат `intl_kk_fixed.arb`, `glossary.csv` и `evidence_by_human`. Активированное окружение с CLI должно оставаться доступным.

```cmd
python -m locqa check --source evidence_by_human\normalized\intl_ru.arb --target intl_kk_fixed.arb --glossary glossary.csv --with-meta --out verification\report.json
python -m locqa validate intl_kk_fixed.arb --template evidence_by_human\normalized\intl_ru.arb
```

Проверка записывает отдельный результат в `verification` и не заменяет сдаваемые отчёты. Для проверенного комплекта ожидаются **139 основных находок, 368 кандидатов и `OK`**.

Для стандартной Flutter-проверки:

```cmd
cd evidence_by_human
flutter --version
flutter pub get
flutter gen-l10n
echo %ERRORLEVEL%
cd ..
```

Ожидаемый код — `0`. В этой папке уже есть `pubspec.yaml`, `l10n.yaml` и нормализованные ru/kk. Файл `normalized\intl_kk.arb` должен совпадать с корневым `intl_kk_fixed.arb`. При изменении итогового перевода обновите проверочную копию. В папке генерации должна быть одна копия каждой локали.

Приложенный лог проверки: `evidence_by_human/flutter-gen-l10n.log`. Версия: `evidence_by_human/flutter-version-current.txt`. Проверка выполнена на Flutter 3.47.9 stable и Dart 3.13.7. Это проверка генерации локализаций, а не сборка всей игры или проверка размещения текста в виджетах.

## Тесты и измерения

Из папки исходного кода:

```cmd
python -m unittest discover -s tests -v
python -m locqa eval --report out\examples_report.json --answer examples\expected_kk.json --json out\examples_metrics.json
```

В проверенной Linux-среде проходят все 112 тестов. На компьютере команды с Windows прошли 111; один тест символических ссылок пропущен из-за ограничений ОС. Некоторые JavaScript-тесты требуют установленного Node.js.

На подготовленных примерах найдены 25 из 25 известных ошибок по типу. Это самопроверка на открытом наборе, а не скрытый recall организаторов.

Расширенный синтетический замер без API:

```cmd
python -m scripts.quality_benchmark --source examples\intl_ru.arb --target examples\intl_kk.arb --other examples\intl_uz.arb --glossary glossary.csv --seeds 5 --min-confidence 0.5 --out out\benchmark.json
```

Результаты и ограничения измерений описаны в METHODOLOGY. Старые замеры CLI `seed` до версии 0.1.2 требуют повторения из-за исправленного дефекта сохранения изменений.

Историческую оценку по решениям Димаша можно воспроизвести из корня репозитория:

```cmd
python -m locqa eval --report evidence_by_human\review\dimash_original_sample_100.json --decisions evidence_by_human\review\dimash_decisions_100.json --json verification\baseline_precision.json
```

Ожидается **0.57 по 100 находкам**. Это результат исходной версии. Он не выдаётся за независимую precision текущей версии 0.1.2. Пустой файл `--answer` для такой оценки не требуется.

## Дополнительная проверка Gemini

Этот раздел выполняется из папки исходного кода. Установка клиента и пример ограниченного запуска:

```cmd
python -m pip install ".[llm]"
set "GEMINI_API_KEY=ВАШ_КЛЮЧ"
python -m locqa check --source examples\intl_ru.arb --target examples\intl_kk.arb --glossary glossary.csv --llm --llm-model gemini-3.1-flash-lite --llm-max 10 --with-meta --out out\gemini_report.json
```

Не сохраняйте ключ в коде, отчётах или архиве сдачи. Запуск обращается к внешнему API и расходует его квоту.

Gemini получает ограниченный набор находок и предлагает исправления в JSON. Ответы повторно проверяются на ID, обязательные поля, ICU и плейсхолдеры; применяются также эвристики языка, терминологии и длины. Исправления не записываются в ARB автоматически. Для временных ошибок предусмотрены ограниченные повторы. Поддержка кэша не заявляется: повторный запуск может отправить новые запросы.

По сведениям команды, фактические денежные затраты составили **$0**: использован бесплатный тариф проекта Default Gemini Project без подключённого платного биллинга. Поле `cost_usd=null` в технической статистике означает, что CLI сам не рассчитывает стоимость. Числа токенов отдельного запуска не являются суммарным расходом проекта.

## Ограничения текущего результата

В итоговом файле остаются четыре пустых фрагмента составных фраз и два предупреждения об окончаниях. Нужен контекст использования в игре. Глоссарий содержит 52 термина; автоматически применяются только 7 терминов со `status=approved`, остальные 45 имеют `status=reference` и служат справочником переводов. Правила могут давать ложные предупреждения в отдельных контекстах. В частности, словоформы и переносы строк ограничивают точность языковых эвристик.

Исправленный файл содержит **114 подтверждённых текстовых изменений**. Это не означает, что проверена вся локализация. Новая независимая ручная precision версии 0.1.2 не измерена. Скрытый recall и слепую оценку исправлений определяет жюри.

Полный список аргументов доступен через `python -m locqa --help` и справку каждой команды.
